    Library Tour

    The standard library, one task per chapter: files, the terminal, formats, HTTP and networking, databases, cryptography and more. Read the Language Tour first.

    1. 1JSONThe json module turns a struct marked @json into JSON text and reads it back. The compiler writes the code for each struct, so nothing is looked up by name at run time.
    2. 2FilesThe fs module reads and writes files and folders. The path module joins paths and takes them apart. Paths are strs written with /.
    3. 3TimeThe time module gives the current time, a clock for measuring, and dates: making them, taking them apart, writing them and reading them back. Lengths of time are Durations, the numbers with units like 250ms from Integers.
    4. 4Input, output and loggingA program reads input from standard input. It writes its results to standard output and messages about itself to standard error. print writes to standard output. The io module reads standard input and writes to either output. The log module writes lines with the time and a level to standard error.
    5. 5Command-line flagsA struct marked @flags describes the flags a program takes. The flags module fills it from the program's arguments. The compiler writes the table of flags for each struct and builds the help from it.
    6. 6Programs and the environmentA program deals with the system around it through its arguments, the environment variables, the other programs it runs, and the signals it receives. The os, process and signal modules cover them.
    7. 7Terminal output and inputA command-line program talks to a person at a terminal, and often to other programs through a pipe. The term module writes colors, status lines, tables and progress bars when a person is watching, and plain text when the output goes to a pipe or a file. It also reads lines with editing and a history, and reads passwords without showing them.
    8. 8Configuration filesA program's settings come from a file, from environment variables, or from both. The toml and ini modules read the two most common file formats. env reads the environment and .env files. Each of them can fill a struct, so the rest of the program reads its settings as plain fields.
    9. 9Regular expressionsThe regex module finds patterns in text. It uses the RE2 syntax: \d+ is one or more digits, (\w+) a group of word characters, a|b either one. A search takes time in proportion to the length of the text, whatever the pattern, so a pattern from a user can't make a program hang.
    10. 10CSV and XMLSpreadsheets, exports and reports often come as CSV, and many older services and feeds use XML. The csv module reads and writes comma-separated values. The xml module reads a document into a tree or one step at a time, and writes one back.
    11. 11Encodings and idsBytes often travel as text: in a header, a URL, a JSON field or a log line. The base64 and hex modules write any bytes as text and read them back. url takes URLs apart and escapes their parts. uuid makes the ids that services hand out.
    12. 12TemplatesA template is text with places for values: an HTML page, an email, a config file for another program. The template module reads a template once and fills it from a @json struct or a Map as often as needed. Values are escaped for HTML unless the template says otherwise, so text from users can't add tags to a page.
    13. 13Compression and archivesThe compress module makes data smaller with gzip and zlib, the formats behind .gz files and HTTP compression. The tar and zip modules pack many files into one, for backups, releases and downloads. All three work on data in memory, so they combine with each other and with the fs module.
    14. 14HTTPThe http module has a server and a client. The server's Router sends each request to the function for its method and path. Both sides speak HTTP/1.1 and HTTP/2, and both do HTTPS.
    15. 15NetworkingThe net module has TCP, UDP, TLS and Unix sockets. A call that waits for the network lets the other tasks on its thread run, so a server can hold many connections with one task each and no callbacks. This chapter starts with a server and a client and goes on to what a proxy needs: socket options, half-closing, copying between connections and looking at the first bytes.
    16. 16Sending emailServices send mail for sign-ups, password resets, alerts and reports. The smtp module sends it through a mail server over SMTP, with TLS and a login.
    17. 17SQLiteThe sqlite module keeps data in a SQLite database, in one file or in memory, with tables read and changed with SQL. The system's SQLite is loaded the first time a program opens a database, so a program that uses it needs SQLite installed.
    18. 18PostgreSQL and RedisA service that runs on more than one machine keeps its data on a database server. The pg module talks to PostgreSQL and the redis module to Redis or Valkey, both over the network with nothing else to install. Each keeps a pool of connections that every task and thread of a program can share, and the pool module gives the same for any other kind of connection.
    19. 19Random numbers and cryptographyThe random module gives random numbers for picking, shuffling and simulations, and random bytes for secrets. The crypto module hashes, signs and encrypts, and jwt builds signed login tokens on top of it. All of them run in the program itself, with no library to install.
    20. 20Math and big numbersThe math module has the functions of floating point math, such as roots, powers, logarithms and trigonometry, and careful integer helpers. Integers and Floating point show the basics. This chapter puts them to work and then turns to the big module, for whole numbers too large for an i64.
