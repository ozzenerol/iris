    Library Tour

    The standard library, one task per chapter: files, the terminal, formats, HTTP and networking, databases, cryptography and more. Read the Language Tour first.

    1. Programs and the system

    1. 1.1FilesThe fs module reads and writes files and folders. The path module joins paths and takes them apart. Paths are strs written with /.
    2. 1.2TimeThe time module gives the current time, a clock for measuring, and dates: making them, taking them apart, writing them and reading them back. Lengths of time are Durations, the numbers with units like 250ms from Integers.
    3. 1.3Input, output and loggingA program reads input from standard input. It writes its results to standard output and messages about itself to standard error. print writes to standard output. The io module reads standard input and writes to either output. The log module writes lines with the time and a level to standard error.
    4. 1.4Command-line flagsA struct marked @flags describes the flags a program takes. The flags module fills it from the program's arguments. The compiler writes the table of flags for each struct and builds the help from it.
    5. 1.5Programs and the environmentA program deals with the system around it through its arguments, the environment variables, the other programs it runs, and the signals it receives. The os, process and signal modules cover them.
    6. 1.6Terminal output and inputA command-line program talks to a person at a terminal, and often to other programs through a pipe. The term module writes colors, status lines, tables and progress bars when a person is watching, and plain text when the output goes to a pipe or a file. It also reads lines with editing and a history, and reads passwords without showing them.
    7. 1.7Configuration filesA program's settings come from a file, from environment variables, or from both. The toml and ini modules read the two most common file formats. env reads the environment and .env files. Each of them can fill a struct, so the rest of the program reads its settings as plain fields.
    8. 1.8Machine numbersThe sys module reads what the Linux kernel counts about the machine: CPU time, load, memory and swap, uptime, OOM kills, network and disk traffic, mounts, and the memory and CPU time of a process. Each call reads one file under /proc and gives a snapshot. It runs on Linux only. Elsewhere every call fails with SysError.notFound.
    9. 1.9Metrics and tracingThe metrics module counts what a program does and writes the counts in the Prometheus text format, for Prometheus to read from a /metrics path. The tracing module records spans, the steps of a request with when each started and ended. It sends them to an OpenTelemetry collector, and follows a request from one program to the next with the W3C traceparent header.

    2. Text and data

    1. 2.1JSONThe json module turns a struct marked @json into JSON text and reads it back. The compiler writes the code for each struct, so nothing is looked up by name at run time.
    2. 2.2Regular expressionsThe regex module finds patterns in text. It uses the RE2 syntax: \d+ is one or more digits, (\w+) a group of word characters, a|b either one. A search takes time in proportion to the length of the text, whatever the pattern, so a pattern from a user can't make a program hang.
    3. 2.3CSV and XMLSpreadsheets, exports and reports often come as CSV, and many older services and feeds use XML. The csv module reads and writes comma-separated values. The xml module reads a document into a tree or one step at a time, and writes one back.
    4. 2.4Encodings and idsBytes often travel as text: in a header, a URL, a JSON field or a log line. The base64, base32 and hex modules write any bytes as text and read them back. url takes URLs apart and escapes their parts. uuid makes the ids that services hand out.
    5. 2.5TemplatesA template is text with places for values: an HTML page, an email, a config file for another program. The template module reads a template once and fills it from a @json struct or a Map as often as needed. Values are escaped for HTML unless the template says otherwise, so text from users can't add tags to a page.
    6. 2.6Compression and archivesThe compress module makes data smaller with gzip and zlib, the formats behind .gz files and HTTP compression. The tar and zip modules pack many files into one, for backups, releases and downloads. All three work on data in memory, so they combine with each other and with the fs module.
    7. 2.7Binary messagesThe wire module reads binary messages into a struct marked @wire and writes them back. Many TCP and UDP protocols send messages like this: a header of fixed fields, then text or lists with their length in front. The compiler works out the layout of each struct when it builds the program, so reading a message is one pass over its bytes, with no lookups at run time.
    8. 2.8MessagePack and CBORMessagePack and CBOR are binary forms of the values JSON has: numbers, text, bools, null, arrays and maps. A message takes fewer bytes than its JSON and is faster to read. The msgpack and cbor modules work the same way. Each reads and writes @json structs, and each has a Value for data of any shape.

    3. Networking

    1. 3.1HTTPThe http module has a server and a client. The server's Router sends each request to the function for its method and path. Both sides speak HTTP/1.1 and HTTP/2, and both do HTTPS.
    2. 3.2NetworkingThe net module has TCP, UDP, TLS and Unix sockets. A call that waits for the network lets the other tasks on its thread run, so a server can hold many connections with one task each and no callbacks. This chapter starts with a server and a client and goes on to what a proxy needs: socket options, half-closing, copying between connections and looking at the first bytes.
    3. 3.3QUIC and HTTP/3QUIC carries connections over UDP with TLS 1.3 built in. One connection holds many streams, and a packet lost on one stream doesn't hold up the others. HTTP/3 is HTTP over QUIC. The quic module has a client and a server. The http module serves and asks for HTTP/3 with the same handlers, Router and Client as HTTP/1.1 and HTTP/2.
    4. 3.4Protocol Buffers and gRPCProtocol Buffers (protobuf) is a binary message format with a number for each field. gRPC sends protobuf messages over HTTP/2 to call a function on a server. The proto module reads and writes messages from structs, and the grpc module is a client and a server.
    5. 3.5MQTTMQTT carries small messages between devices and services through a broker. A client publishes a message to a topic, such as home/kitchen/temp, and the broker passes it to every client subscribed to that topic. The mqtt module is a client for MQTT 5 and 3.1.1 brokers such as Mosquitto, and a broker of its own.
    6. 3.6Sending emailServices send mail for sign-ups, password resets, alerts and reports. The smtp module sends it through a mail server over SMTP, with TLS and a login.
    7. 3.7SSHSSH runs commands on other machines, copies files to them and reaches ports behind them. The ssh module is a client and a server. The client logs in to OpenSSH servers and others and runs commands. The server takes logins from ssh, sftp and other clients, and runs shells and commands for them.
    8. 3.8SFTP and scpSFTP works on the files of an SSH server: it copies them, lists folders, renames and removes. It runs over an SSH connection, so it logs in and checks the server as SSH does. The ssh module has its client and its server, and copies with scp for servers that have no SFTP.
    9. 3.9S3Files that many machines share often go to an object store: Amazon S3, or a server that speaks its API, such as MinIO, Ceph or Cloudflare R2. The s3 module stores, reads, lists and removes objects, uploads big ones in parts, and makes links that work without keys. The sigv4 module signs the requests, and signs requests to the other AWS APIs too.
    10. 3.10Certificates with ACMEHTTPS needs a certificate that browsers trust. Let's Encrypt and other certificate authorities issue them for free to whoever shows they control a domain, through a protocol named ACME. The acme module registers an account, proves control of domains and gets the certificate and its key.

    4. Databases

    1. 4.1SQLiteThe sqlite module keeps data in a SQLite database, in one file or in memory, with tables read and changed with SQL. The system's SQLite is loaded the first time a program opens a database, so a program that uses it needs SQLite installed.
    2. 4.2PostgreSQL and RedisA service that runs on more than one machine keeps its data on a database server. The pg module talks to PostgreSQL and the redis module to Redis or Valkey, both over the network with nothing else to install. Each keeps a pool of connections that every task and thread of a program can share, and the pool module gives the same for any other kind of connection.
    3. 4.3MySQLThe mysql module talks to MySQL and MariaDB over the network, with nothing else to install. It has the same shape as the pg module of the PostgreSQL and Redis chapter: a pool that every task and thread can share, exec and query, rows read into @json structs with mysql.all and mysql.one, and transactions.
    4. 4.4MongoDBThe mongo module talks to MongoDB over the network, with nothing else to install. Documents are @json structs, turned into MongoDB's binary format, BSON, by the bson module. A mongo.Client keeps a pool of connections that every task and thread can share.
    5. 4.5Rows as structsA struct marked @entity is a row of a database table. The sqlite, pg and mysql modules then add it, read it by its key, write it back and remove it, with the SQL made from the struct. This chapter uses SQLite, whose examples run without a server. The PostgreSQL and MySQL modules have the same calls.
    6. 4.6MigrationsA schema changes as a program grows: new tables, new columns, new indexes. The migrate module keeps those changes as numbered migrations, runs the ones a database hasn't had, and remembers which ran. It works with the sqlite, pg, mysql and mongo modules of the earlier chapters.

    5. Numbers and security

    1. 5.1Random numbers and cryptographyThe random module gives random numbers for picking, shuffling and simulations, and random bytes for secrets. The crypto module hashes, signs and encrypts, and jwt builds signed login tokens on top of it. All of them run in the program itself, with no library to install.
    2. 5.2Math and big numbersThe math module has the functions of floating point math, such as roots, powers, logarithms and trigonometry, and careful integer helpers. Integers and Floating point show the basics. This chapter puts them to work and then turns to the big module, for whole numbers too large for an i64.
