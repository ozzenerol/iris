    Programs and the environment

    A program deals with the system around it through its arguments, the environment variables, the other programs it runs, and the signals it receives. The os, process and signal modules cover them.

    Arguments

    os.argc() gives how many arguments the program got, counting its own name. os.arg(i) gives one of them as a str. Argument 0 is the program's name, and past the end os.arg gives "".

    import os

void main() {
    print("this is {os.arg(0)}, with {os.argc() - 1} arguments")

    for i in 1..os.argc() {
        print("argument {i}: {os.arg(i)}")
    }
}

    ./show a "b c" prints:

    this is ./show, with 2 arguments
argument 1: a
argument 2: b c

    A program with flags reads them into a struct with flags.parse instead (see Command-line flags).

    Exit status

    A program that ends normally has status 0. When main returns !void and ends with an error, the program prints the error and ends with status 1. os.exit(code) ends the program at once with any status, and defer blocks don't run.

    import os

void main() {
    if os.argc() < 2 {
        print("usage: probe <host>")
        os.exit(2)
    }

    print("probing {os.arg(1)}")
}

    Environment variables

    os.env(name) gives a variable's value as a !str. A variable that isn't set gives the error OsError.notSet, so catch can supply a default.

    import os

void main() {
    path := os.env("PATH") catch ""
    print("PATH is set: {path.len > 0}")

    upstream := os.env("IRIS_TOUR_UPSTREAM") catch "127.0.0.1:9000"
    print("the upstream is {upstream}")

    _ = os.env("IRIS_TOUR_UPSTREAM") catch err {
        print("{err.code}: {err.message}")
        ""
    }
}
    PATH is set: true
the upstream is 127.0.0.1:9000
OsError.notSet: IRIS_TOUR_UPSTREAM is not set

    os.setenv(name, value) sets a variable for the program and for the programs it runs from then on. os.unsetenv(name) removes one. An invalid name, empty or containing =, fails with OsError.invalid.

    import os, process, str

!void main() {
    try os.setenv("UPSTREAM", "10.0.0.11:9000")
    print(try os.env("UPSTREAM"))

    scoped out := try process.run(["sh", "-c", "echo $UPSTREAM"])
    print("sh sees: {str.trim(out.stdout)}")

    try os.unsetenv("UPSTREAM")
    print(os.env("UPSTREAM") catch "not set")
}
    10.0.0.11:9000
sh sees: 10.0.0.11:9000
not set

    Set variables at the start, before the program starts threads. Changing the environment while another thread reads it isn't safe.

    For a program's settings, a struct marked @env reads every variable at once, with types and defaults (see Attributes).

    Running other programs

    process.run(argv) runs a program and waits for it to end. argv[0] is the program, looked up on PATH when it has no /. The rest are its arguments, passed as they are. No shell is involved, so spaces and quotes need no escaping. It returns an Output with what the program wrote and its exit status.

    import process, str

!void main() {
    scoped out := try process.run(["echo", "listening on", "8080"])
    print("status {out.status}, ok {out.ok()}")
    print("it printed: {str.trim(out.stdout)}")
}
    status 0, ok true
it printed: listening on 8080

    Output owns stdout and stderr. Its free method frees them, so scoped works on it.

    A program that ends with a status other than 0 is no error, and status says how it ended. run fails only when the program can't be started, with ProcessError.notFound when it doesn't exist.

    import process, str

!void main() {
    scoped out := try process.run(["sh", "-c", "echo oops >&2; exit 3"])
    print("status {out.status}, ok {out.ok()}, stderr: {str.trim(out.stderr)}")

    _ = process.run(["no-such-program"]) catch err {
        print("{err.code}: {err.message}")
        process.Output{}
    }
}
    status 3, ok false, stderr: oops
ProcessError.notFound: no-such-program: no such program

    A shell command with pipes and > runs through sh -c, as above.

    Programs that run beside this one

    process.start(argv) starts a program and returns at once with a Child. The program shares this one's standard input, output and error. wait waits for it to end and gives its exit status, while the other tasks run. running says whether it still runs, stop asks it to end (SIGTERM) and kill ends it at once (SIGKILL). A program a signal ended has the status 128 plus the signal's number.

    import process

!void main() {
    sleeper := try process.start(["sleep", "10"])
    print("running: {sleeper.running()}")
    sleeper.stop()
    print("ended with {sleeper.wait()}")

    job := try process.start(["sh", "-c", "exit 4"])
    print("the job ended with {job.wait()}")
}
    running: true
ended with 143
the job ended with 4

    keep hands the program open descriptors, which it gets as 3, 4 and so on, in order. A server upgrades this way without dropping a connection: it starts its next version with its listening socket, the new process takes it with net.adoptListener(3) and accepts on it, and the old one stops accepting and lets its own connections finish. Here the program starts itself again as its next version. Built with iris build and run, it prints served by the new version:

    import net, os, process

!void next() {
    ln := try net.adoptListener(3)
    defer ln.close()
    c := try ln.accept()
    defer c.close()
    try c.write("served by the new version\n")
}

!void main() {
    if os.argc() > 1 && os.arg(1) == "--next" {
        try next()
        return
    }
    ln := try net.listen(0, "127.0.0.1")
    port := ln.port
    newer := try process.start([os.arg(0), "--next"], keep: [ln.fd()])
    ln.close() // the new version has its own copy of the socket

    c := try net.dial("127.0.0.1", port)
    defer c.close()
    scoped String line = try c.readLine()
    print(line)
    _ = newer.wait()
}

    Connections that wait to be accepted stay in the socket's queue while the versions change, so none is refused. os.arg(0) is the program's own path. iris run deletes the program it built once the program starts, so a program that starts itself has to be built.

    process.startWith(argv, options) starts a program set up as a process.Options says. Each field left out is as start has it.

    • env holds NAME=value entries that replace or add to this program's environment, and with cleanEnv they are the whole of it.
    • dir is the folder it starts in, and argv0 its argv[0]: -bash starts a login shell.
    • pipes makes its standard input, output and error connections on the Child, stdin, stdout and stderr, which this program writes and reads like any net.Conn. closePipes closes them.
    • newSession puts it in a session and process group of its own, so signal.sendGroup(child.pid, s) reaches it and everything it starts.
    • user runs it as another user, in that user's groups; only root may.
    • keep hands it descriptors, as with start.
    import process, str

!void main() {
    c := try process.startWith(["tr", "a-z", "A-Z"], process.Options{pipes: true, env: ["LC_ALL=C"]})
    try c.stdin.write("shout this\n")
    try c.stdin.closeWrite()
    scoped String out = try c.stdout.readAll()
    print(str.trim(out))
    print("status {c.wait()}")
    c.closePipes()
}
    SHOUT THIS
status 0

    Programs on a terminal

    A shell, an editor or top wants a terminal, not pipes. pty.open(rows, cols) makes a pseudo-terminal: a terminal side for the program and this side, which reads what the program writes and writes what it reads, as an SSH server or a terminal emulator does. Options.terminal takes terminalFd(), and the program then has the terminal as its standard input, output and error and as its controlling terminal, in a session of its own. Once it has started, closeTerminal() closes this program's copy, so read gives 0 when the program and everything it started have closed it.

    import process, pty, str

!void main() {
    t := try pty.open(rows: 24, cols: 80)
    defer t.close()
    child := try process.startWith(["sh", "-c", "stty size; tty > /dev/null && echo on a terminal"], process.Options{terminal: t.terminalFd()})
    t.closeTerminal()

    String all
    defer all.free()
    u8[256] buf
    for {
        n := try t.read(buf[:])
        if n == 0 {
            break
        }
        all.append(buf[0:n])
    }
    _ = child.wait()
    for line in str.lines(str.trim(all)) {
        print(str.trim(line))
    }
}
    24 80
on a terminal

    write sends what the program reads, as if typed: "\x03" is Ctrl-C. resize(rows, cols) changes the size, and the program gets windowChange. setFlag(.echo, false) and the other pty.Flags set termios's flags, and setChar(.interrupt, 3) the characters with a meaning, which is what SSH's terminal modes carry. setSpeed(baud) sets the speed for programs that ask.

    Running as another user

    A server that listens on a port below 1024 starts as root, binds its ports, and then gives up root with os.runAs(user). From then on every thread of the program runs as that user, in its groups and its own group, or in group when one is given. The program can't become root again, and on Linux it also loses every capability. The sockets it already has keep working.

    import net, os

!void main() {
    ln := try net.listen(443)
    try os.runAs("www-data")
    print("serving as {os.uid()}")
    // accept on ln as www-data
}

    On Linux, keep holds on to some of root's power: os.runAs("vpn", keep: [.netAdmin]) leaves the program able to set up interfaces and routes, and nothing else, and .netBindService lets it bind ports below 1024 later. The thread that calls runAs keeps them, and the threads it starts after, so a program calls it before it starts its threads. os.hasCapability(.netAdmin) says whether the thread has one.

    Only root may change to another user: anyone else gets OsError.permission, except when asking for the user and group the program already runs as, which does nothing. A user or group that doesn't exist gives OsError.notFound. os.uid() and os.gid() give the ids the program runs as, and os.user() the user's name.

    os.lookupUser(name) and os.lookupUserId(uid) give a User from the system's user database: its name, uid, gid, home, shell and gecos, and groups(), the ids of every group it is in. os.lookupGroup(name) and os.lookupGroupId(gid) give a Group with its name, gid and members.

    import os

!void main() {
    scoped root := try os.lookupUser("root")
    print("{root.name} is {root.uid}, in group {root.gid}")
}
    root is 0, in group 0

    os.cpuCount() is how many cores the program may run on, and os.pinThread(core), on Linux, keeps the calling thread on one of them, so a thread per core keeps its caches warm.

    Limits and sandboxes

    os.setLimit(.openFiles, 4096) sets a resource limit, and os.limit(l) reads one as its soft and hard values: open descriptors, processes, the largest file, memory, CPU seconds and the others of os.Limit. A server that holds many connections raises .openFiles first.

    A program that parses what comes from the network can shut itself in, so a bug in that code reaches little. os.chroot(dir) makes a folder the root of what it can see, which only root may do, before it gives up root with runAs. os.noNewPrivileges() stops any program it starts from gaining privileges. On Linux, os.allowSyscalls(["openat", ...]) lets only the system calls named through from then on, for every thread, besides those the runtime makes itself to run tasks and use what it has open; any other fails with permission denied, or with kill: true ends the program.

    import os

!void main() {
    try os.setLimit(.openFiles, 1024)
    try os.allowSyscalls([])
    // from here the program can read and write the sockets it has, and
    // nothing else: opening a file fails with FsError.permission
}

    Input

    The second argument to run goes to the program's standard input:

    import process, str

!void main() {
    scoped out := try process.run(["sort", "-u"], "10.0.0.9\n10.0.0.5\n10.0.0.9\n10.0.0.7\n")
    print(str.trim(out.stdout))

    scoped count := try process.run(["wc", "-l"], "GET /\nGET /login\nPOST /login\n")
    print("{str.trim(count.stdout)} requests")
}
    10.0.0.5
10.0.0.7
10.0.0.9
3 requests

    While a program runs, the thread's other tasks keep going (see Tasks and channels). A server that runs a program keeps answering.

    Signals

    Ctrl-C sends a program the signal interrupt. systemd and Docker send terminate to stop it. By default either one ends the program at once. signal.wait() waits for one instead and returns it as a signal.Signal, so the program can finish its work first.

    import process, signal

!void main() {
    signal.watch()

    // stands in for Ctrl-C: sh sends terminate to this program, its parent
    scoped out := try process.run(["sh", "-c", "kill -TERM $PPID"])

    s := signal.wait()
    print("got {s}, saving and stopping")
}
    got terminate, saving and stopping

    From then on, signal.watch() makes interrupt and terminate wait for wait instead of ending the program. wait calls it when nothing is watched yet. signal.watch([.hangup]) watches other signals. Many programs take hangup (SIGHUP) as a request to read their settings again. user1 and user2 (SIGUSR1 and SIGUSR2) mean whatever the program says, such as starting its next version. child comes when a program this one started ends, windowChange when the terminal changes size, and quit is Ctrl-\\.

    signal.send(pid, s) sends a signal to another process, and signal.sendGroup(group, s) to every process of a process group. Besides the ones above, kill ends a process at once, pause stops it and resume lets it go on; those three can be sent but not watched. A process that isn't there gives SignalError.notFound, and one this program may not signal SignalError.permission.

    A server waits for the signal in one task while other tasks serve:

    import signal

void serve() {
    // answers requests until the program ends
}

void main() {
    spawn serve()

    s := signal.wait()
    print("got {s}, stopping")
    // close connections, flush files, then return
}

    When main returns, the program ends and the other tasks with it.
