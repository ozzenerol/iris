    SSH

    SSH runs commands on other machines, copies files to them and reaches ports behind them. The ssh module is a client and a server. The client logs in to OpenSSH servers and others and runs commands. The server takes logins from ssh, sftp and other clients, and runs shells and commands for them.

    Running a command

    ssh.dial(host, port, config) connects, checks the server's key, logs in and gives a Client. run(command) runs a command and waits for it to end. It gives the command's output, its errors and its exit status in a process.Output (see Processes):

    import ssh

!void main() {
    scoped key := try ssh.loadKey("/home/ada/.ssh/id_ed25519")
    c := try ssh.dial("db1.example.com", 22, ssh.Config{user: "ada", key: &key})
    defer c.close()

    scoped out := try c.run("df -h /var")
    print(out.stdout)
    if !out.ok() {
        print("df failed with {out.status}: {out.stderr}")
    }
}

    A status other than 0 is no error: the command ran and ended that way. The errors are SshError codes:

    • connect: the server can't be reached.
    • hostKey: its key isn't the one known for it.
    • auth: the login is refused.
    • closed: the connection went away.

    run(command, input) also gives the command something to read on its standard input.

    Logging in

    Config.key is the key to log in with. loadKey reads a private key file as ssh-keygen writes it: Ed25519, ECDSA on P-256, P-384 or P-521, or RSA, and the older PEM files of the last two. A key with a passphrase takes it too, as in loadKey(path, passphrase). Config.password logs in with a password instead. With both, the key is tried first.

    ssh.generateKey(comment) makes a new Ed25519 key. ssh.generateKeyOf(.ecdsaP256, comment) makes another kind (ecdsaP384, ecdsaP521, or rsa with a size in bits, 3072 unless given). privateText() gives it in the format of ~/.ssh/id_ed25519, and privateText(passphrase) encrypts it with the passphrase as ssh-keygen does. publicText() gives the line that goes in a server's ~/.ssh/authorized_keys:

    import ssh, str

void main() {
    scoped key := ssh.generateKey("deploy@ci")
    scoped String private = key.privateText()
    scoped String public = key.publicText()
    scoped String fingerprint = key.fingerprint()
    scoped List[str] lines = str.lines(private)
    scoped List[str] fields = str.fields(public)
    print(lines.at(0))
    print("{fields.at(0)} ... {fields.at(2)}")
    print("{fingerprint[0:7]} and {fingerprint.len - 7} more characters")
}
    -----BEGIN OPENSSH PRIVATE KEY-----
ssh-ed25519 ... deploy@ci
SHA256: and 43 more characters

    fingerprint() is the key's hash as ssh-keygen -l shows it.

    The server's key

    Before it logs in, dial checks that the server is the one it should be. As ssh does, it looks the server's key up in ~/.ssh/known_hosts, with hashed names too, and with [host]:port for a port other than 22. Config.knownHosts names another file. The server's key can be Ed25519, ECDSA on P-256, P-384 or P-521, or RSA. When the file has a key of one of these types for the server, dial asks the server for that type first.

    A server that isn't in the file is refused with SshError.hostKey. The message has the server's fingerprint and the line to add once the fingerprint is checked. A server whose key has changed is refused too. Config.hostKey gives the key directly, as a public key line or a SHA256: fingerprint. Client.serverKey is the key the server showed. Config.anyHostKey trusts any key and is only for tests.

    Output as it comes

    exec(command) starts a command and gives a Channel without waiting for the command to end. read gives its output as it comes, readStderr its errors, and write gives it input. closeWrite ends the input, and wait gives the exit status once the command ends:

    ch := try c.exec("journalctl -f -u nginx")
defer ch.close()
u8[] buf = alloc(u8, 32KiB)
defer free(buf)
for {
    n := try ch.read(buf)
    if n == 0 {
        break
    }
    io.write(buf[0:n])
}
print("ended with {ch.wait()}")

    shell() starts the user's shell on a terminal, as ssh does when it logs in. resize(rows, cols) gives the terminal a new size, and signal("INT") sends the command a signal. subsystem(name) starts one of the server's subsystems. Files are copied with sftp() or scpUpload (see SFTP and scp).

    A connection carries many channels at once, each with its own flow, so a slow reader of one doesn't hold up the others. Several tasks can each run their own command on one Client. A Client and its channels stay on the thread that made them.

    Reaching a port behind the server

    forward(host, port) opens a connection from the server to host:port, as ssh -L does. What is written to the Channel goes there, and what comes back can be read. pipe(&conn) copies between the channel and a net.Conn both ways until both ends are done. Here a local port reaches a database that only the server can see:

    import net, ssh

void tunnel(ssh.Client *c, net.Conn local) {
    defer local.close()
    ch := c.forward("10.0.0.5", 5432) catch e {
        return
    }
    defer ch.close()
    ch.pipe(&local)
}

!void main() {
    scoped key := try ssh.loadKey("/home/ada/.ssh/id_ed25519")
    c := try ssh.dial("bastion.example.com", 22, ssh.Config{user: "ada", key: &key})
    defer c.close()
    ln := try net.listen(15432, "127.0.0.1")
    for {
        local := try ln.accept()
        spawn tunnel(&c, local)
    }
}

    A port on the server

    listen(host, port) asks the server to listen on a port for the client, as ssh -R does. Each connection made to it comes as a Channel from accept. Port 0 lets the server choose, and port says which it took. close asks it to stop:

    rl := try c.listen("localhost", 8080)
defer rl.close()
for {
    ch := try rl.accept()
    spawn serveVisitor(ch)
}

    Agents

    An agent holds private keys and signs with them, so that programs that log in never see the keys. ssh.agent() connects to the one in SSH_AUTH_SOCK, as ssh-agent sets it, and Config.agent logs in with its keys after Config.key:

    a := try ssh.agent()
defer a.close()
c := try ssh.dial("db1.example.com", 22, ssh.Config{user: "ada", agent: &a})

    keys() lists what the agent holds as public key lines, add(&key) gives it a key as ssh-add does, and remove and removeAll take keys out. Config.forwardAgent lets commands on the server use the agent, as ssh -A does. ssh.serveAgent(listener) is an agent itself, on a net.listenUnix socket, and ssh-add and ssh work with it.

    Certificates

    A certificate is a key signed by a certificate authority, for some users or host names and for some time. A server that trusts the authority takes every user it signed, with no authorized_keys to keep, and a client that trusts it takes every host it signed. signCertificate signs one with the authority's key, as ssh-keygen -s does, and setCertificate gives a key its certificate:

    import ssh

void main() {
    scoped ca := ssh.generateKey("ca")
    scoped user := ssh.generateKey("ada@laptop")
    scoped String userLine = user.publicText()
    scoped String line = ca.signCertificate(userLine, ssh.CertOptions{keyId: "ada", principals: ["ada", "deploy"],
        validBefore: 2000000000}) catch "".copy()
    scoped cert := ssh.parseCertificate(line) catch ssh.Certificate{}
    print("{cert.keyId} for {cert.principals.len} users, host {cert.host}, valid now {cert.validAt(1800000000)}")
}
    ada for 2 users, host false, valid now true

    loadKey also reads the certificate ssh-keygen -s writes next to the key, in <path>-cert.pub, and dial shows it before the plain key. On the server, Server.userCAs holds the authorities' public key lines. A certificate logs in as one of its principals, and its force-command and source-address options are kept. On the client, a @cert-authority line in known_hosts trusts the host certificates an authority signed. A server shows its certificate when its hostKey has one.

    A server

    An ssh.Server holds the server's own key and the functions that decide things. password and publicKey each take a user and a password or a key and say whether the login is allowed. A way of logging in whose function is null isn't offered. handle runs each shell, command or subsystem a client asks for. ssh.serve(port, server) listens and serves each connection in a task.

    The handler gets a Session, with the user, the kind (shell, exec or subsystem) and the command. It reads and writes the session and sets status, the exit status the client gets when the handler returns. This program runs a server and a client together:

    import net, ssh

ssh.Key userKey

bool checkKey(str user, str key) {
    scoped String want = userKey.fingerprint()
    scoped String got = ssh.fingerprint(key) catch "".copy()
    return user == "ada" && got == want
}

!void handle(ssh.Session *s) {
    if s.command == "uptime" {
        try s.write("up 41 days\n")
        return
    }
    try s.writeStderr("{s.command}: not found\n")
    s.status = 127
}

void serveOn(net.Listener ln, ssh.Server s) {
    ssh.serveOn(ln, s) catch e { }
}

!void main() {
    userKey = ssh.generateKey()
    scoped hostKey := ssh.generateKey()
    ln := try net.listen(0, "127.0.0.1")
    spawn serveOn(ln, ssh.Server{hostKey: hostKey, publicKey: checkKey, handle: handle})

    scoped String known = hostKey.publicText()
    c := try ssh.dial("127.0.0.1", ln.port, ssh.Config{user: "ada", key: &userKey, hostKey: known})
    defer c.close()
    scoped up := try c.run("uptime")
    print("{up.stdout.trim()} ({up.status})")
    scoped bad := try c.run("reboot")
    print("{bad.stderr.trim()} ({bad.status})")
}
    up 41 days (0)
reboot: not found (127)

    The server's key is kept in a file, so clients find the same key each time. Make it once with generateKey and write privateText() to a file only the server can read. loadKey reads it back at the start.

    Running programs for a session

    Session.run(argv) runs a program for the session, as sshd does. When the client asked for a terminal, as ssh does for a shell, the program runs on a pseudo-terminal of the client's size, and a resize reaches it. Otherwise its standard input, output and errors are joined to the session's. Its exit status is the session's. When the client goes away, the program and what it started get a hangup.

    process.Options sets the rest (see Processes): user runs it as the user who logged in, which needs root, and dir starts it in their home. ssh.authorizedKey(path, key) looks a key up in an authorized_keys file, and shadow.checkLogin checks a password against the system's (see Random numbers and cryptography):

    import os, process, shadow, ssh

bool checkPassword(str user, str password) => shadow.checkLogin(user, password) catch false

bool checkKey(str user, str key) {
    scoped u := os.lookupUser(user) catch e {
        return false
    }
    return ssh.authorizedKey("{u.home}/.ssh/authorized_keys", key)
}

!void handle(ssh.Session *s) {
    scoped u := try os.lookupUser(s.user)
    o := process.Options{user: s.user, dir: u.home}
    if s.kind == .subsystem {
        if s.command == "sftp" {
            _ = try s.run(["/usr/lib/openssh/sftp-server"], o)
        }
        return
    }
    if s.kind == .shell {
        _ = try s.run([u.shell, "-l"], o)
        return
    }
    _ = try s.run([u.shell, "-c", s.command], o)
}

!void main() {
    hostKey := try ssh.loadKey("/etc/iris-ssh/host_key")
    try ssh.serve(2222, ssh.Server{hostKey: hostKey, password: checkPassword, publicKey: checkKey, handle: handle})
}

    ssh -p 2222 ada@host, scp -P 2222 and sftp -P 2222 all work with it. ssh.serveSftp(s, root) serves SFTP without OpenSSH's program (see SFTP and scp). Server.forward takes a user, a host and a port and says whether that user may reach it through the server with ssh -L. While it is null, forwarding is refused. Server.remoteForward says the same for ports the server listens on for a user with ssh -R. Server.agentForwarding lets sessions use the client's agent with ssh -A: Session.agentSocket is its socket, and programs that run starts find it in SSH_AUTH_SOCK.

    What it speaks

    Connections use the mlkem768x25519-sha256 key exchange, as OpenSSH does since 10.0. It joins ML-KEM-768 with X25519, so that what is recorded now can't be read later by a quantum computer. With a side that doesn't have it, they use curve25519-sha256. The ciphers are AES-256-GCM, AES-128-GCM and ChaCha20-Poly1305. Both sides make new keys after Config.rekeyAfter bytes, 1 GiB unless set, and whenever the other side asks. The key exchange is the strict one, which OpenSSH added against the Terrapin attack. Keys are Ed25519, ECDSA on P-256, P-384 and P-521, and RSA with SHA-256 or SHA-512, for users, servers and certificates.
