    Language Tour

    The whole language, one topic per chapter, with runnable programs and their output. Read it in order once, then use it as the reference.

    Basics

    1. A first program
    The parts of every Iris program: main, statements, blocks and comments, and the commands that build and run it.
    2. Variables
    How to declare variables, change them, and where each one is visible.
    3. Integers
    The integer types, their literals, arithmetic, and conversion between them.
    4. Floating point
    The two float types, their literals and printing, and how they mix with integers.
    5. Booleans and operators
    The bool type, the operators, and the order in which an expression is evaluated.
    6. Text
    Iris has two text types. A str views text stored elsewhere. A String owns its text and can grow. This chapter covers both, text literals, and the methods on text.
    7. Values in text
    Interpolating values with braces, the format function, and how temporary text is freed.
    8. if and match
    if chooses by condition and match by value. Both can produce a value.
    9. Loops
    for is the only loop. It has four forms: forever, while a condition holds, over a range, and over items. break and continue control it.

    Functions and data

    10. Functions
    Declaring functions, default and named arguments, variadic parameters, and returning several values.
    11. Functions as values
    Functions can be stored in variables and struct fields and passed as arguments.
    12. Arrays and slices
    An array holds a fixed number of values in a row. A slice views some of them, or memory from alloc, and knows its length. Most functions take slices.
    13. Structs
    A struct groups named values into one type. This chapter covers declaring structs, literals and defaults, copying and comparing, embedding, and memory layout.
    14. Methods
    A method is a function that belongs to a struct. This chapter covers self, constructor and free conventions, and the methods the language itself calls.
    15. Enums
    An enum is a type with a fixed list of values. Plain enums name choices and codes. Flags enums hold any set of their values. Enums with data carry fields per value.
    16. Tuples and type aliases
    Tuples carry a function's several results. Type aliases give a type a second name.

    Memory and errors

    17. Pointers
    A pointer holds the address of a value, so code can read and change the value in place. This chapter covers addresses, dereferencing, null, and how long a pointer stays valid.
    18. Errors
    A function that can fail says so in its type and returns either its result or an error. The caller must pass the error up with try or handle it with catch. This chapter covers creating, propagating and handling errors, the trace printed when an error leaves main, and panic for bugs.
    19. Memory
    Iris has no garbage collector. Memory that a program asks for, it gives back. This chapter covers where values live, alloc and free, the statements that make freeing hard to forget (defer, errdefer and scoped), arenas, who frees what, and the checks that catch mistakes.

    Building larger programs

    20. Generics
    A generic function or struct is written once, with type parameters, and used with many types. This chapter covers both, how the types are worked out, and how generic code is compiled.
    21. Interfaces
    An interface is a list of methods. A struct with those methods has the interface, with nothing more to write. Interfaces work in two ways: as bounds on type parameters, resolved at compile time, and as dyn values, resolved at run time.
    22. Collections
    23. Modules
    A program is split into modules. A module is a folder of files that share their names and show other modules only what they mark pub. This chapter covers programs and projects, pub, import, the standard library, and packages from other projects.

    Concurrency

    24. Tasks and channels
    A task is a function call that runs alongside the rest of the program. Tasks take turns on a thread and switch whenever one waits, so a program can do many things at once without callbacks. Channels pass values between them. This chapter covers spawn, channels, select and timers.
    25. Threads
    Threads run at the same time on different CPU cores. This chapter covers starting and joining them, sharing data between them with Atomic and Mutex, and threadlocal.

    Going further

    26. Compile time
    The compiler can do work while it builds the program: constants, values computed by running code before the program exists, and code kept or left out by the platform it is built for. There is no preprocessor and there are no macros. All of this is ordinary Iris.
    27. Attributes
    An attribute starts with @ and goes on the line before a declaration. Some make the compiler write code for a struct that reads it from environment variables, from command-line flags, from JSON or from binary messages. Others change how a function is compiled. This chapter covers each one except @json, @entity, @wire and @flags, which have their own chapters: JSON, Rows as structs, Binary messages and Command-line flags. A struct can have several, one to a line, such as @json and @entity.
    28. Calling C
    Iris calls C functions directly, with no wrapper code to write. import c reads a C header and makes its functions, types and constants available. C can also call Iris functions back. This chapter covers both, how C types look in Iris, and the rules for text and memory at the border.
    29. Testing
    Tests sit next to the code they test, in test blocks, and iris test runs them. This chapter covers writing tests, checking with expect, tests that use errors, running them, and measuring speed with bench blocks.
    30. Tools
    The iris command builds, runs, tests, formats and documents programs, gets packages and serves editors. This chapter covers each command, the build modes, building for other platforms, editors and debuggers.
