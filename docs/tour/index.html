    Language Tour

    Every part of the language, and the library modules almost every program uses, one topic per chapter, explained fully and with many small programs and their output. Read it in order the first time; later, use it as the reference.

    1. 1A first programWhat every Iris program is made of: main, statements, blocks, comments, and the commands that build and run it.
    2. 2VariablesDeclaring variables, giving them values, and where each one can be used.
    3. 3IntegersThe integer types, how integer literals are written, how arithmetic works on them, and how values move from one type to another.
    4. 4Floating pointNumbers with a fraction: the two types, how they are written and printed, and how they mix with integers.
    5. 5Booleans and operatorsThe bool type, the operators that combine and compare values, and the order in which a longer expression is worked out.
    6. 6TextIris has two types for text. A str looks at text that is stored somewhere else; a String owns its text and can grow. This chapter covers both, the ways to write text in the program, and the methods that work on it.
    7. 7Values in textPutting values into text with braces, the format function that keeps the result, and how the temporary text is freed for you.
    8. 8if and matchChoosing what runs: if for conditions, match for picking one of many values. Both can also give a value.
    9. 9Loopsfor is the only loop, and it has four forms: forever, while a condition holds, over a range of numbers, and over the items of something. break and continue change its course.
    10. 10FunctionsDeclaring functions, passing them arguments, giving defaults and names to those arguments, and returning one value or several.
    11. 11Functions as valuesA function can be kept in a variable, passed to another function and stored in a struct. This chapter covers function types and what can be done with them.
    12. 12Arrays and slicesAn array is a fixed number of values stored one after another. A slice looks at some of them, or at memory from alloc, and knows how many there are. Slices are how most functions take a list of things.
    13. 13StructsA struct puts several values together into one type, each with a name. This chapter covers declaring structs, making values of them, defaults, copying and comparing, embedding one struct in another, and how a struct's fields are laid out in memory.
    14. 14MethodsA method is a function that belongs to a struct. This chapter covers declaring them, what self is, the conventions for making and freeing values, and methods that make a type work with the rest of the language.
    15. 15EnumsAn enum is a type with a fixed list of values. Plain enums name choices and codes; flag enums hold any set of their values at once; and the values of an enum with data each carry fields of their own.
    16. 16Tuples and type aliasesTuples are the several values a function gives back. Type aliases give another name to a type. Both are small, and both make other code easier to read.
    17. 17PointersA pointer holds the address of a value, so code can read and change the value where it is instead of a copy of it. This chapter covers taking addresses, reading and writing through pointers, null, and the rules that keep pointers valid.
    18. 18ErrorsA function that can fail says so in its type, and gives either its result or an error. The caller must do something with the error: pass it up with try, or handle it with catch. Nothing can be ignored by accident. This chapter covers making errors, passing them on, handling them, the trace a program prints when one reaches the end of main, and panic for bugs.
    19. 19MemoryIris has no garbage collector: memory that a program asks for, it gives back. This chapter covers where values live, alloc and free, the statements that make freeing hard to forget (defer, errdefer and scoped), arenas, who frees what, and the checks that catch mistakes.
    20. 20GenericsA generic function or struct is written once, with type parameters, and used with many types. This chapter covers both, how the types are worked out, and how generic code is compiled.
    21. 21InterfacesAn interface is a list of methods. A struct with those methods has the interface; nothing more needs to be written. Interfaces are used in two ways: as bounds on type parameters, worked out when compiling, and as dyn values, worked out when the program runs.
    22. 22CollectionsList keeps values in order and grows as values are added; Map keeps a value for each key, and Set keeps each value once. Deque is a queue open at both ends, Heap gives back the value that goes first, and SortedMap keeps its keys in order. All of them, and the functions on slices, are in every module without an import. This chapter covers what they do, how loops go over them, and who frees what they hold.
    23. 23ModulesA program is split into modules: folders of files that share their names, and show other modules only what they mark pub. This chapter covers programs and projects, pub, import, the standard library, and packages from other projects.
    24. 24Tasks and channelsA task is a function call that runs alongside the rest of the program. Tasks take turns on a thread, switching whenever one waits, so a program can do many things at once without callbacks. Channels pass values between them. This chapter covers spawn, channels, select and timers.
    25. 25ThreadsThreads run at the same time, on different CPU cores. This chapter covers starting and joining them, sharing data between them with Atomic and Mutex, and threadlocal.
    26. 26Compile timeWork the compiler does while it builds the program: constants, values worked out by running code before the program exists, and code that is kept or left out by the platform it is built for. There is no preprocessor and no macros; all of this is ordinary Iris.
    27. 27AttributesAn attribute starts with @ and goes on the line before a declaration. Some make the compiler write code for a struct: reading it from environment variables, from command-line flags, or from JSON. Others change how a function is compiled. This chapter covers each one except @json and @flags, which have their own chapters: JSON and Command-line flags.
    28. 28JSONA struct marked @json can be turned into JSON text and read back from it, with the json module. The compiler writes the code for each struct, so there are no lookups by name while the program runs.
    29. 29FilesThe fs module reads and writes files and folders, and the path module joins paths and takes them apart. Paths are strs, written with /.
    30. 30Command-line flagsA struct marked @flags describes the flags a program takes, and the flags module fills it from the program's arguments. The compiler writes the table of flags for each struct, and the help is made from it.
    31. 31TimeThe time module has the current time, a clock for measuring, and dates: making them, taking them apart, writing them and reading them back. Lengths of time are Durations, the numbers with units like 250ms from Integers.
    32. 32Input, output and loggingA program reads its input from standard input, and has two places to write text: standard output, for what it gives as its result, and standard error, for what it says about itself while it runs. print writes to standard output. The io module reads standard input and writes to either output, and the log module writes lines with the time and a level to standard error.
    33. 33HTTPThe http module has a server, with a Router that sends each request to the function for its method and path, and a client. Both speak HTTP/1.1 and HTTP/2, and both do HTTPS.
    34. 34NetworkingThe net module has TCP, UDP, TLS and Unix sockets. A call that waits for the network lets the other tasks on its thread run, so a server can hold many connections with one task each and no callbacks. This chapter goes from a server and a client to the parts a proxy needs: socket options, half-closing, copying between connections and looking at the first bytes.
    35. 35SQLiteThe sqlite module keeps data in a SQLite database: one file, or memory, with tables read and changed with SQL. The system's SQLite is loaded the first time a program opens a database, so a program that uses it needs SQLite installed.
    36. 36Programs and the environmentA program talks to the system around it in four ways: the arguments it was started with, the environment variables, the other programs it runs, and the signals it gets. The os, process and signal modules cover them.
    37. 37Regular expressionsThe regex module finds patterns in text. The syntax is that of RE2: \d+ is one or more digits, (\w+) a group of word characters, a|b either one. A search takes time in proportion to the length of the text, whatever the pattern, so a pattern that comes from a user can't make a program hang.
    38. 38Configuration filesA program's settings come from a file, from environment variables, or from both. The toml and ini modules read the two most common file formats, and env reads the environment and .env files. All of them can fill a struct, so the rest of the program reads its settings as plain fields.
    39. 39CSV and XMLSpreadsheets, exports and reports often come as CSV, and many older services and feeds speak XML. The csv module reads and writes comma-separated values, and the xml module reads a document into a tree or a step at a time, and writes one back.
    40. 40Encodings and idsBytes often have to travel as text: in a header, a URL, a JSON field or a log line. The base64 and hex modules write any bytes as text and read them back, url takes URLs apart and escapes their parts, and uuid makes the ids that services hand out.
    41. 41Random numbers and cryptographyThe random module gives random numbers, for picking, shuffling and simulations, and random bytes for secrets. The crypto module hashes, signs and encrypts, and jwt builds signed tokens for logins on top of it. All of them run in the program itself, with no library to install.
    42. 42Compression and archivesThe compress module makes data smaller with gzip and zlib, the formats behind .gz files and HTTP compression. The tar and zip modules pack many files into one, for backups, releases and downloads. All three work on data in memory, so they combine with each other and with the fs module.
    43. 43TemplatesA template is text with places for values: an HTML page, an email, a config file for another program. The template module reads a template once and fills it in from a @json struct or a Map as often as needed. Values are escaped for HTML unless the template says otherwise, so text from users can't add tags to a page.
    44. 44PostgreSQL and RedisA service that runs on more than one machine keeps its data on a database server. The pg module talks to PostgreSQL and the redis module to Redis or Valkey, both over the network with nothing else to install. Each keeps a pool of connections that every task and thread of a program can share, and the pool module gives the same for any other kind of connection.
    45. 45Terminal output and inputA command-line program talks to a person at a terminal, and often to other programs through a pipe as well. The term module writes colors, status lines, tables and progress bars when a person is watching, and plain text when the output goes to a pipe or a file. It also reads lines with editing and a history, and passwords without showing them.
    46. 46Sending emailServices send mail for sign-ups, password resets, alerts and reports. The smtp module sends it through a mail server over SMTP, the way a mail program does, with TLS and a login.
    47. 47Math and big numbersThe math module has the functions of floating point math, such as roots, powers, logarithms and trigonometry, and careful integer helpers. Integers and Floating point show the basics. This chapter puts them to work, and then turns to the big module, for whole numbers too large for an i64.
    48. 48Calling CIris calls C functions directly, with no wrapper code to write: import c reads a C header and makes its functions, types and constants available. C can also call Iris functions back. This chapter covers both, how C types look in Iris, and the rules for text and memory at the border.
    49. 49TestingTests sit next to the code they test, in test blocks, and iris test runs them. This chapter covers writing tests, checking with expect, tests that use errors, running them, and measuring how fast code is with bench blocks.
    50. 50ToolsThe iris command builds, runs, tests, formats and documents programs, gets packages, and serves editors. This chapter covers each command, the build modes, building for other platforms, editors and debuggers.
