    Language Tour

    Every part of the language, one topic per chapter, explained fully and with many small programs and their output. Read it in order the first time; later, use it as the reference.

    1. 1A first programWhat every Iris program is made of: main, statements, blocks, comments, and the commands that build and run it.
    2. 2VariablesDeclaring variables, giving them values, and where each one can be used.
    3. 3IntegersThe integer types, how integer literals are written, how arithmetic works on them, and how values move from one type to another.
    4. 4Floating pointNumbers with a fraction: the two types, how they are written and printed, and how they mix with integers.
    5. 5Booleans and operatorsThe bool type, the operators that combine and compare values, and the order in which a longer expression is worked out.
    6. 6TextIris has two types for text. A str looks at text that is stored somewhere else; a String owns its text and can grow. This chapter covers both, the ways to write text in the program, and the methods that work on it.
    7. 7Values in textPutting values into text with braces, the format function that keeps the result, and how the temporary text is freed for you.
    8. 8if and matchChoosing what runs: if for conditions, match for picking one of many values. Both can also give a value.
    9. 9Loopsfor is the only loop, and it has four forms: forever, while a condition holds, over a range of numbers, and over the items of something. break and continue change its course.
    10. 10FunctionsDeclaring functions, passing them arguments, giving defaults and names to those arguments, and returning one value or several.
    11. 11Functions as valuesA function can be kept in a variable, passed to another function and stored in a struct. This chapter covers function types and what can be done with them.
    12. 12Arrays and slicesAn array is a fixed number of values stored one after another. A slice looks at some of them, or at memory from alloc, and knows how many there are. Slices are how most functions take a list of things.
    13. 13StructsA struct puts several values together into one type, each with a name. This chapter covers declaring structs, making values of them, defaults, copying and comparing, embedding one struct in another, and how a struct's fields are laid out in memory.
    14. 14MethodsA method is a function that belongs to a struct. This chapter covers declaring them, what self is, the conventions for making and freeing values, and methods that make a type work with the rest of the language.
    15. 15EnumsAn enum is a type with a fixed list of values. Plain enums name choices and codes; flag enums hold any set of their values at once; and the values of an enum with data each carry fields of their own.
    16. 16Tuples and type aliasesTuples are the several values a function gives back. Type aliases give another name to a type. Both are small, and both make other code easier to read.
    17. 17PointersA pointer holds the address of a value, so code can read and change the value where it is instead of a copy of it. This chapter covers taking addresses, reading and writing through pointers, null, and the rules that keep pointers valid.
    18. 18ErrorsA function that can fail says so in its type, and gives either its result or an error. The caller must do something with the error: pass it up with try, or handle it with catch. Nothing can be ignored by accident. This chapter covers making errors, passing them on, handling them, the trace a program prints when one reaches the end of main, and panic for bugs.
    19. 19MemoryIris has no garbage collector: memory that a program asks for, it gives back. This chapter covers where values live, alloc and free, the statements that make freeing hard to forget (defer, errdefer and scoped), arenas, who frees what, and the checks that catch mistakes.
    20. 20GenericsA generic function or struct is written once, with type parameters, and used with many types. This chapter covers both, how the types are worked out, and how generic code is compiled.
    21. 21InterfacesAn interface is a list of methods. A struct with those methods has the interface; nothing more needs to be written. Interfaces are used in two ways: as bounds on type parameters, worked out when compiling, and as dyn values, worked out when the program runs.
    22. 22CollectionsList keeps values in order and grows as values are added; Map keeps a value for each key, and Set keeps each value once. Deque is a queue open at both ends, Heap gives back the value that goes first, and SortedMap keeps its keys in order. All of them, and the functions on slices, are in every module without an import. This chapter covers what they do, how loops go over them, and who frees what they hold.
    23. 23ModulesA program is split into modules: folders of files that share their names, and show other modules only what they mark pub. This chapter covers programs and projects, pub, import, the standard library, and packages from other projects.
    24. 24Tasks and channelsA task is a function call that runs alongside the rest of the program. Tasks take turns on a thread, switching whenever one waits, so a program can do many things at once without callbacks. Channels pass values between them. This chapter covers spawn, channels, select and timers.
    25. 25ThreadsThreads run at the same time, on different CPU cores. This chapter covers starting and joining them, sharing data between them with Atomic and Mutex, and threadlocal.
    26. 26Compile timeWork the compiler does while it builds the program: constants, values worked out by running code before the program exists, and code that is kept or left out by the platform it is built for. There is no preprocessor and no macros; all of this is ordinary Iris.
    27. 27AttributesAn attribute starts with @ and goes on the line before a declaration. Some make the compiler write code for a struct: reading it from environment variables, from command-line flags, or from JSON. Others change how a function is compiled. This chapter covers each one except @json and @flags, which have their own chapters: JSON and Command-line flags.
    28. 28Calling CIris calls C functions directly, with no wrapper code to write: import c reads a C header and makes its functions, types and constants available. C can also call Iris functions back. This chapter covers both, how C types look in Iris, and the rules for text and memory at the border.
    29. 29TestingTests sit next to the code they test, in test blocks, and iris test runs them. This chapter covers writing tests, checking with expect, tests that use errors, running them, and measuring how fast code is with bench blocks.
    30. 30ToolsThe iris command builds, runs, tests, formats and documents programs, gets packages, and serves editors. This chapter covers each command, the build modes, building for other platforms, editors and debuggers.
