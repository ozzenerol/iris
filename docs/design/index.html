    Design

    The compiler's architecture: the passes, their data structures, the runtime, and where to start reading the source.

    1. Overview
    What Iris is for, the path from source to program, and where each part lives in the source tree.
    2. Loading and parsing
    How the compiler finds the files of a program, turns them into tokens and builds the syntax tree.
    3. The checker
    How src/check.c resolves names, works out types, lays out structs, makes generic instances and runs comptime.
    4. The IR writer
    How src/ir.c turns the checked tree into LLVM IR text, and how src/main.c hands that text to clang.
    5. How values are stored
    What each Iris type looks like in memory and in LLVM IR. llType in src/ir.c maps a Type to its IR type, and typeSize and typeAlign in src/check.c give its size and alignment.
    6. The runtime
    What runtime/rt.c does and how the generated code uses it. The runtime is one C file, carried inside the iris binary and compiled with every program (see The IR writer). Its exported functions start with iris_. The generated code calls the ones writeIR declares, and the standard library calls the rest through @extern.
    7. Decisions
    The rules Iris follows and the reason for each, the ones still proposed, and the features Iris leaves out. Where a rule shapes the compiler or the runtime, the other Design pages show how.
    8. Working on Iris
    Where to start reading for a change, and how changes are built, tested and released. This applies to people and to agents.
